# Issues

Include as much data as possible, ideally a stack trace, your operating system, exact nightly commit (or pinned release version), dependencies, rockspec files, etc.

# Pull Requests

I (David Cruz) do not have much time to spend on reviews and managing pull requests, and the codebase is not as clean as I would like it for new maintainers to drop in with minimal effort.

Regardless, pull requests are welcome, but if the quality of the code would require more effort in terms of reviewing and maintaining, I may prefer to make my own changes instead.

## Style

Follow the [STYLE.md](./STYLE.md) guide.

## Tests

Fixes and features MUST be accompanied by integration tests ensuring no regressions occur.

# LLMs

Usage of LLMs is fine. You are responsible for the quality of the code generated in terms of style, verbosity, performance and simplicity.
